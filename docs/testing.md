### 1. Команди запуску тестів

#### Backend (Python / FastAPI)
* **Запуск усіх юніт- та інтеграційних тестів:**
  ```bash
  pytest
  ```
* **Запуск тестів із детальним виводом (verbose):**
  ```bash
  pytest -v
  ```
* **Запуск із перевіркою покриття коду (coverage):**
  ```bash
  pytest --cov=. --cov-report=term-missing
  ```
* **Швидка перевірка доступності сервера (Healthcheck через curl):**
  ```bash
  curl -X GET http://127.0.0.1:8000/health
  ```

#### Android Client (Gradle / Kotlin)
* **Запуск локальних модульних тестів (Unit Tests):**
  ```bash
  ./gradlew testDebugUnitTest
  ```
* **Запуск інструментальних тестів на емуляторі/пристрої (UI & Instrumental Tests):**
  ```bash
  ./gradlew connectedDebugAndroidTest
  ```

### 2. Обов'язкові сценарії тестування (Test Scenarios)

#### Сценарій 1: Успішне структурування списку справ (Checklist)
* **Вхід:** Текст із переліком дій або покупок (наприклад: `"купити молоко і хліб, написати звіт"`).
* **Очікуваний результат:**
  * HTTP-код `200 OK`.
  * `category` відповідає контексту (`"Покупки"` або `"Робота"`).
  * `format_type == "CHECKLIST"`.
  * `structured_content` містить пункти у форматі `- [ ] ...`.
  * `has_reminder == false`, `reminder_datetime == null`.

#### Сценарій 2: Виявлення дедлайну та створення нагадування
* **Вхід:** Текст із часовим маркером (наприклад: `"завтра о 15:00 зустріч з науковим керівником"`).
* **Очікуваний результат:**
  * `has_reminder == true`.
  * `reminder_datetime` містить валідну майбутню дату у форматі `YYYY-MM-DD 15:00` (розраховану від поточної дати).
  * `category == "Навчання"`.

#### Сценарій 3: Форматування суцільного тексту (Text Formatting)
* **Вхід:** Довга неструктурована думка без списків і без дат (роздуми, ідеї, конспект).
* **Очікуваний результат:**
  * `format_type == "TEXT"`.
  * `structured_content` розбитий на логічні абзаци з роздільником `\n\n`.
  * `has_reminder == false`.

#### Сценарій 4: Валідація некоректного вводу (Edge Cases & Validation)
* **Вхід:**
  * Порожній рядок або рядок лише з пробілів (`"   "`).
  * Занадто короткий текст (`"ок"` — менше 3 символів).
* **Очікуваний результат:**
  * Клієнт блокує надсилання та переводить UI у `UiState.Error("Введіть щонайменше 3 символи")`.
  * Бекенд на прямий запит повертає HTTP `422 Unprocessable Entity` або HTTP `400 Bad Request`.

#### Сценарій 5: Робота резервного рушія (Fallback Engine)
* **Умова:** `GEMINI_API_KEY` не заданий у `.env` або штучно спровоковано збій виклику AI (timeout/quota).
* **Вхід:** Валідний текст нотатки.
* **Очікуваний результат:**
  * Сервер повертає HTTP `200 OK` (не падає з кодом `500`).
  * Поле `reasoning` містить мітку про обробку локальним евристичним рушієм.
  * Категорія та структура визначаються за базовими ключовими словами.

#### Сценарій 6: Обробка мережевих помилок на клієнті (Error State & Retry)
* **Умова:** Бекенд вимкнено або відсутнє підключення до мережі.
* **Дія:** Користувач натискає «Обробити через AI Backend».
* **Очікуваний результат:**
  * UI переходить зі стану `Loading` у `UiState.Error`.
  * Відображається людинозрозуміле повідомлення (наприклад: `"🔌 Сервер недоступний"`).
  * Доступна активна кнопка «Повторити спробу» (`Retry`), введений текст не стирається.
