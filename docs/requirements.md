### 1. Реалізовані вимоги (Implemented Requirements)

* **Ввід сирого тексту нотатки:**
  * Текстове поле в Compose UI з валідацією мінімальної довжини (від 3 символів) та захистом від надсилання порожнього тексту.
* **Автоматична категоризація та генерація заголовка:**
  * Формування стислої назви (3–5 слів) за змістом замітки.
  * Класифікація за фіксованими категоріями: «Навчання», «Робота», «Покупки», «Особисте», «Плани», «Здоров'я».
* **Форматування та структурування вмісту:**
  * Визначення типу розмітки (`TEXT`, `CHECKLIST`, `BULLET_LIST`).
  * Перетворення переліку задач на чекліст із маркерами `- [ ]` або розбиття суцільного тексту на охайні абзаци.
* **Виявлення часових сутностей та нагадувань:**
  * Розпізнавання відносних часових маркерів («завтра», «у п'ятницю», «о 16:00») відносно поточного серверного часу.
  * Розрахунок точної дати та часу у форматі `YYYY-MM-DD HH:MM` (`has_reminder = true/false`).
* **Клієнт-серверний контракт та Fallback-обробка:**
  * FastAPI бекенд із Pydantic-валідацією схем запиту (`text`) та відповіді.
  * Резервний евристичний рушій [`local_analyze`] у разі відсутності `GEMINI_API_KEY` або помилок мережі/квот.
* **Управління станами інтерфейсу:**
  * Повна реактивна обробка 4 станів `UiState`: `Idle`, `Loading` (індикатор прогресу), `Success` (картка результату), `Error` (зрозумілий опис помилки та кнопка «Повторити спробу»).

### 2. Незавершені функції (Pending / In-Progress Features)

* **Локальне сховище даних (Local Persistence):**
  * Інтеграція Room SQLite для збереження нотаток на пристрої після схвалення пропозиції AI.
* **Планувальник системних сповіщень:**
  * Реєстрація розпізнаних нагадувань у системі Android через `AlarmManager` / `WorkManager` та показ Push-повідомлень.
* **Семантичний пошук нотаток:**
  * Векторизація тексту за допомогою локальних ембедингів і пошук за сенсом (а не тільки за точним збігом слів).
* **Повноцінний екран ручного редагування / модерації:**
  * Можливість безпосередньо у формі перед збереженням змінити згенерований заголовок, змінити категорію чи скоригувати дату нагадування (концепція «Людина схвалює або виправляє»).
* **Керування налаштуваннями:**
  * Збереження налаштувань підключення (URL сервера) та власного API ключа через `DataStore`.

### 3. Критерії готовності (Definition of Done)

* **Функціональні критерії:**
  * Сирий текст довжиною від 3 до 2000 символів успішно приймається додатком, надсилається на бекенд і повертається у валідному форматі `NoteAnalyzeResponse`.
  * При наявності згадки дій чи дедлайнів формується прапорець `has_reminder = true` з валідною майбутньою датою у форматі `YYYY-MM-DD HH:MM`.
  * При втраті інтернет-з'єднання чи недоступності AI API користувач бачить зрозуміле повідомлення про помилку з можливістю повторного запиту (`Retry`), або бекенд повертає евристичний результат без аварійного завершення (код 500).
* **Технічні критерії:**
  * Всі вхідні та вихідні JSON відповідають затвердженим Pydantic-схемам контракту.
  * Відсутність блокування основного UI-потоку Android (мережеві операції суворо в `Dispatchers.IO`).
  * Час обробки запиту через хмарну модель не перевищує клієнтського таймауту (15 секунд).
